# CONTRIBUTING : comment améliorer ce curriculum

Ce dépôt se dégrade si on y ajoute du contenu tiède. La barre est haute exprès.

## Avant d'ajouter une page

Réponds à ces trois questions dans la description de ta contribution :

1. **Quel échec réel cette page évite-t-elle ?** Décris une situation vue, pas une notion manquante.
2. **Quel est le coût de la bonne pratique proposée ?** Une recommandation sans coût est une opinion.
3. **Sera-t-elle vraie dans cinq ans ?** Sinon, elle va dans `15-BONUS-VAULT/`, et chaque exemple
   de code volatil (version d'outil, seuil de performance) porte dans le commentaire de son bloc
   de code la mention `# verifie le AAAA-MM-JJ`, au format déjà en usage dans
   `05-DATA-SPELLS/grimoire.md` et `09-QUALITY-SHIELD/grimoire.md`.

## Format obligatoire d'une leçon

Voir `_STYLE.md`. En résumé : une scène concrète, le modèle mental, un diagramme ASCII, du code
minimal, un tableau de compromis, les pièges avec leur symptôme observable, et trois questions de
défense orale.

## Rejets automatiques

- Emojis.
- Exemples todo-list, blog, e-commerce générique.
- Listes de définitions sans conséquence pratique.
- Contenu généré sans relecture : on le repère aux paragraphes qui n'engagent rien.
- Toute page qui ne pourrait pas être défendue à l'oral en trois minutes.

## Corriger plutôt qu'ajouter

Le meilleur type de contribution est une correction : un exemple faux, un compromis mal chiffré, un
piège manquant. Une page existante améliorée vaut mieux qu'une page de plus.

## Traductions

Le français est la langue source. Une traduction doit garder le ton direct et le tutoiement.
